# 설계 결정 기록

## D1. 궤도 크기는 장반경 a 대신 반통경 p로 저장 (1단계)
- a는 포물선에서 무한대, 쌍곡선에서 음수가 되어 한 타입으로 다루기 불편하다.
- p는 모든 원뿔곡선에서 양의 유한값이다. a는 `Elements.a` 속성으로 계산해 제공한다.

## D2. 특이 궤도의 각도 규약 (1단계)
- 적도 궤도(i ≈ 0, π): raan = 0, 기준축은 관성 x축.
- 원 궤도(e ≈ 0): argp = 0, ν는 승교점(적도 궤도면 x축)부터 잰다.
- Vallado의 진경도·위도인수 개념을 별도 필드 없이 기존 6요소에 담는 방식이다.
  `coe_to_rv(rv_to_coe(r, v))`가 특이 궤도에서도 항등이 되는 것을 테스트로 보장한다.
- 판정 허용오차는 무차원 1e-11 (`CIRCULAR_TOL`, `EQUATORIAL_TOL`).

## D3. core 함수는 스칼라 `math` 기반 (1단계)
- 케플러 방정식·근점이각 변환은 스칼라 float를 받는다. 전파 루프 안에서 호출되므로
  numpy 배열 오버헤드를 피하고 코드를 교과서 공식에 가깝게 유지한다.
- 벡터화가 필요해지면 (예: 궤도 그림용 대량 샘플링) 별도 함수로 추가한다.

## D4. 포물선의 평균근점이각은 Barker 방정식 M = D + D³/3 (1단계)
- `mean_to_true`/`true_to_mean`이 이심률만으로 세 궤도 종류를 자동 처리하도록 하기 위함.

## D5. 단위 라이브러리는 astropy (2단계)
- MVP 이후 UTC/TAI/TDB 변환이 필요한데 `astropy.time`이 이를 제공한다. pint를 쓰면 시간 척도를 따로 구현해야 한다.
- 천문·우주 분야의 사실상 표준이라 대상 사용자가 이미 익숙할 가능성이 높다.
- 단점(설치 크기, Quantity 연산 오버헤드)은 단위 변환을 경계(`units.py`)에서만 하므로 계산 성능에 영향이 없다.

## D6. 맨 숫자는 SI로 간주, 각도 포함 (2단계)
- `to_si(30, ANGLE)`는 30 rad이다. 도 단위는 `30 * u.deg`로 명시해야 한다.
- 각도만 예외로 두면 규칙이 두 개가 되어 실수가 더 늘어난다고 판단했다.

## D7. 시간은 J2000 기준 TDB 경과 초 하나의 float64 (2단계)
- `Epoch(tdb_seconds)`로 캡슐화. 2000~2100년 범위에서 float64 정밀도는 약 1e-7 s로,
  LEO 속도(7.8 km/s)에서 1 mm 미만의 위치 오차라 MVP 정확도 목표에 충분하다.
- 달력·JD 입력은 TDB로 해석한다. TDB 달력은 윤초가 없어 단순 날짜 차이가 정확하다.
- 다른 시간 척도는 `Epoch.from_astropy()`를 거치면 astropy가 변환한다. 자체 변환은 구현하지 않는다.

## D8. Body는 질량 대신 μ(GM)를 저장 (3단계)
- μ는 궤도 관측으로 직접 결정되어 G·M 각각보다 수십만 배 정확하다 (G 자체의 불확도가 약 2e-5).
- 질량은 `Body.mass = μ/G` 속성으로 제공한다. 각 프리셋에 `source`로 상수 출처를 남긴다.

## D9. Orbit의 기준 상태는 상태벡터 (r, v, epoch) (3단계)
- 상태벡터는 원·적도·포물선 궤도에서도 특이점이 없고, 전파기의 입출력 형식과 같다.
- 궤도 요소는 `cached_property`로 한 번만 계산해 둔다. 객체가 불변이라 캐시가 무효화될 일이 없다.
- r, v는 복사 후 읽기 전용 배열로 저장한다. numpy 배열은 값 비교가 모호하므로 `eq=False`(동일성 비교).

## D10. 궤도 프리셋 ISS는 Orbit 객체 (3단계)
- SPEC의 `ISS.orbit.transfer_to(GEO)` 예시는 우주선 객체를 암시하지만, 우주선 객체는 MVP 범위에 없다.
  프리셋 목록(LEO, ISS, GEO, SSO)이 궤도로 분류되어 있어 `ISS.transfer_to(GEO)` 형태로 정했다.
- 프리셋은 대표값이다 (ISS: 420 km 원 궤도, 51.64°). 실제 위치는 TLE로 얻는다.
- GEO 반지름은 지구 자전 각속도로부터, SSO 경사각은 J2 승교점 변화율로부터 계산한다.

## D11. propagate()는 Orbit이 아니라 Trajectory를 돌려준다 (4단계)
- SPEC은 "새 객체 반환"과 "결과 메타데이터 보관"을 함께 요구한다. Orbit에 메타데이터를 섞지 않고,
  시계열(t, r, v) + `PropagationInfo`(모델·적분기·허용오차·가정·종료 사유)를 담은 `Trajectory`를 돌려준다.
- 최종 궤도는 `trajectory.final`, 중간 시점은 `orbit_at(i)`. 시계열은 6단계 `.plot()`에서 그대로 쓴다.

## D12. 2체 모델은 기본적으로 해석해, 그 외는 DOP853 (4단계)
- `method="auto"`: 2체는 케플러 해석해(정확·빠름), J2·항력은 `solve_ivp` DOP853.
  `method="DOP853"`을 명시하면 2체도 수치 적분해 적분기 검증에 쓸 수 있다.
- 기본 허용오차 rtol=1e-12, atol=1e-8. rtol=1e-10이면 이심 궤도 10일 전파에서 해석해 대비 51 m,
  1e-12이면 0.5 m. 비용은 약 1.7배(ISS 30일 j2+drag 약 5.5초). GMAT 대조를 위해 정확도를 택했다.
- 천체 표면 도달 시 적분을 멈추고 `info.terminated`에 기록한다.

## D13. 환경값은 모두 Environment로 통일 (4단계)
- 상수 → `Constant`, 함수 f(r, t) → `Function`, `Environment` 객체는 그대로. `as_environment()`가 변환한다.
- t는 J2000 기준 TDB 초(float). 매 스텝 호출되므로 Epoch 객체를 만들지 않는다.
- 각 Environment는 `description`을 가져 결과 메타데이터의 가정 목록에 들어간다.
- 지구 대기 기본값은 Vallado 표 8-4 지수 모델(`Body.atmosphere`). `density=`로 덮어쓸 수 있다.

## D14. 전파 모듈은 패키지 대신 단일 모듈 propagation.py (4단계)
- SPEC은 `propagation/` 패키지를 제안했지만 현재 규모(약 200줄)에서는 단일 모듈이 읽기 쉽다.
  힘 모델은 `core/forces.py`, 적분은 `core/propagate.py`에 있어 propagation.py는 조립만 한다.
  충실도 3~4단계가 추가되면 패키지로 나눈다.
- 같은 이유로 대기 밀도는 별도 파일 없이 `core/forces.py`(지수 대기 표·밀도 함수)와
  `environment.py`(`ExponentialAtmosphere`)에 둔다. 대기 모델도 Environment 구현체이기 때문이다.
- 2체 해석해도 수치 적분처럼 천체 표면에 닿으면 멈춘다 (샘플 간 brentq로 도달 시각을 구함).

## 메모 (해결됨, 6단계 D19): J2 접촉 장반경 진동
- J2가 있으면 접촉 장반경이 단주기로 크게 진동한다 (ISS 고도에서 0 ~ -12 km). 항력만 넣은 30일 감쇠는 2.65 km인데
  끝 시점만 비교하면 14 km로 보인다. `Trajectory.explain()`이 경고와 1바퀴 평균 변화를, 고도 그림이 1바퀴 이동 평균선을 보여준다.

## D15. 전이는 Δv 공식이 아니라 실제 상태벡터로 구성 (5단계)
- `Transfer`는 기동마다 위치·시각·Δv 벡터를 가진 `Burn`과, 기동 직후 궤도(`orbits`)를 담는다.
  Δv 크기만 주는 공식(core/maneuvers.py)과 별개로, 상태벡터에 Δv를 더하고 기동 사이를 해석해로 이어
  만든다. 6단계 plot()이 그대로 쓰고, 공식과 벡터 결과가 일치하는지 테스트로 교차 검증한다.
- MVP 제약: 시작·목표 궤도는 원 궤도(e ≤ 1e-3), 목표 궤도 안의 위상(랑데부)은 맞추지 않는다.

## D16. 궤도면이 다르면 노드에서 기동하고, 호만 전이의 궤도면 변경은 최적 분배 (5단계)
- 궤도면 변경은 두 궤도면의 교선(노드)에서만 가능하다. 시작 위치가 노드가 아니면 다음 노드까지
  기다린다(`Transfer.coast`). 호만 전이는 반 바퀴라 반대 노드에서 2차 기동이 이루어진다.
- 기본 `plane_split="optimal"`: 두 기동에 궤도면 변경을 나누는 비율을 총 Δv 최소로 정한다
  (ISS→GEO에서 1차 2.89°, 원점 몰아주기보다 약 40 m/s 절약). 0~1 숫자로 직접 지정할 수 있다.
- 이중타원 전이는 속도가 가장 느린 중간 원점에서 궤도면을 모두 바꾼다.

## D17. pytest import 모드는 importlib (5단계)
- `tests/core/test_maneuvers.py`와 `tests/test_maneuvers.py`처럼 core와 객체 계층 테스트가
  같은 파일 이름을 쓰도록 `--import-mode=importlib`을 켰다 (pytest 권장 방식).

## D18. 그림 라벨은 영어 (6단계)
- matplotlib 기본 폰트(DejaVu Sans)에는 한글 글리프가 없어 다른 환경에서 네모로 깨진다.
  폰트 설정을 라이브러리가 바꾸는 것은 사용자 환경 침범이라 하지 않는다. explain() 텍스트는 한국어.
- matplotlib은 plot() 호출 시에만 import한다 (urania import 속도).

## D19. explain()은 Explanation 객체를 돌려주고, 값은 core로 다시 계산해 교차 검증 (6단계)
- 출력 부작용 없이 객체를 돌려준다. `__repr__`이 본문이라 REPL·Jupyter에서 바로 읽히고 print()도 된다.
- 중간값(원 궤도 속도, 전이 타원 속도 등)은 core 함수(`vis_viva`, `combined_dv` …)로 계산한다.
  공식으로 다시 구한 Δv가 상태벡터로 만든 Burn과 어긋나면 경고(`warnings`)에 남긴다.

## D20. 전이 그림은 각 궤도를 자기 궤도면에 펼쳐 그린다 (6단계)
- 한 평면에 투영하면 궤도면이 다른 목표 궤도가 타원으로 찌그러진다. 모든 기동이 노드 축 위에서
  일어나므로, x축을 노드로 두고 궤도마다 (ĥ × x̂)를 y축으로 쓰면 펼친 그림이 서로 이어진다.
- 전파 경로 그림은 시작 궤도면에 투영한다 (J2 세차가 투영으로 보임). 고도 그림은 1바퀴 이동 평균선을 겹친다.

## D21. TLE는 별도 객체 TLEOrbit, SGP4로만 전파 (7단계)
- TLE 요소는 SGP4 전용 평균 요소라 고전 궤도 요소로 쓰면 틀린다. `TLEOrbit`은 `Orbit`과 상속 관계가 없고,
  `propagate()`도 SGP4만 쓴다. 결과는 같은 `Trajectory`라 plot·explain을 그대로 쓴다.
- 자체 전파기로 넘기려면 `to_orbit(epoch)`으로 상태벡터를 꺼내는 명시적 경로만 둔다.
- 생성 시 체크섬과 두 줄의 위성 번호를 검사한다. SGP4 오류(재진입 등)가 나면 그 앞에서 멈추고
  `info.terminated`에 기록한다.

## D22. TLE 좌표계 TEME를 관성계로 그대로 사용 (7단계)
- TEME → GCRF 변환에는 세차·장동 모델이 필요해 MVP 범위(시간·좌표 변환 제외) 밖이다.
- urania 전파기도 "관성 좌표계 축 고정, 자전축 = z축"을 가정한다. TEME의 z축은 그 시각의 실제 자전축이라
  SGP4 결과와 자체 전파기를 비교할 때 오히려 일관된다. 가정 목록에 TEME임을 남긴다.

## D23. TLE 시각(UTC) ↔ Epoch(TDB)는 astropy로 변환 (7단계)
- D7에서 자체 시간 척도 변환은 하지 않기로 했다. TLE epoch과 SGP4 호출 시각 변환만 astropy Time을 거친다.
- 중력 상수는 TLE 생성 규약인 WGS72. `to_orbit()` 이후의 Orbit은 Earth(WGS 84) 상수를 쓴다.

## D24. GMAT 대조는 스크립트 생성기 + 고정 픽스처 (8단계)
- GMAT 출력은 이 저장소에서 만들 수 없으므로 지어내지 않는다. `validation/gmat/make_scripts.py`가 urania 시나리오에서
  GMAT 스크립트를 만들고, 사용자가 GMAT에서 실행한 결과(`tests/fixtures/gmat/*.txt`)를 커밋한다.
  `tests/test_gmat.py`는 픽스처가 없으면 skip한다. 허용 오차는 잠정값이며 실제 데이터를 본 뒤 확정한다.
- 조건을 맞춰 차이 요인을 줄였다: J2000 기준 시각(세차 0), GMAT EGM96 상수로 만든 테스트 천체, RK89 1e-13.
